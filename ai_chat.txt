The one design decision worth knowing about
For the generated web, the model proposes structure only — every number is computed in code. It returns species, who-eats-whom, and trophic level; lib/webgen.ts then derives diet shares (normalised to 1 per predator), predation dependency (capped at 0.7 per prey), baselines, growth rates and carrying capacities.
I did it this way because asking a small model for coefficients that must satisfy “shares sum to 1” and “dependency stays under 1” gives you a web that drifts while nothing is happening — which destroys the whole premise, since the learner can no longer attribute any change to her own action. Asking it whether a frog eats grasshoppers is a question it answers well.
There’s also an ensureDecidable() repair step: if the generated web has no predator with two food sources, it adds one. Without that, no two agents can disagree about something a single run settles, and the activity degrades into a plain simulation.
Two things to be aware of
The login is a classroom gate, not real auth. Passwords sit in an env var in plain text, no database, no reset, no rate limiting. The password never reaches the browser, the cookie is HMAC-signed, and the comparison is timing-safe — but don’t reuse it for anything that matters. It’s flagged as such in the README.
